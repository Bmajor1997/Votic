# Product risks, controls, and verification

Owner for each row: release maintainer (Ben). Severity is a Votic product priority, not a NASA hazard category. Open operational checks block a verified release claim.

| ID / requirement | Risk | Control / implementation | Automated verification | Acceptance / state |
| --- | --- | --- | --- | --- |
| VSAFE-001 Bound untrusted imports | Page can consume stack/CPU and interfere with other users | app_parts/web_import.js, web_import_worker.js, document_parser.js; shared extraction slots in votic_server.js | web_import.test.js: deep/wide HTML, worker deadline/recovery, stuck DNS, stream budget, explicit text limit; votic_server.test.js: shared capacity and health | Implemented; deployed load test pending |
| VSAFE-002 Preserve activity on failed reads | Existing statistics can be overwritten with empty history | ActivityProvider.tsx hydration/write guard and ActivityLoadState.tsx retry | activityRecovery.test.tsx: rejected read, malformed history, retry, queued events | Implemented; device storage fault test pending |
| VSAFE-003 Bound document metadata | Damaged metadata requests huge allocations | documentStorage.ts: <=20 chunks of <=500k chars, <=2000 documents, bounded identifiers and positions, <=1.5 MB metadata preflight; backup model uses same limits | documentStorage.test.ts: extreme counts/positions and pre-write rejection | Implemented; existing data retained on rejected loads |
| VSAFE-004 Preserve account identity and deletion | Cross-account disclosure or resurrected deleted data | accountStorage, accountDeletion, AccountDataProvider, backend verified identity | accountIsolation/accountDeletion integration tests; root account_deletion.test.js | Live Firebase/RevenueCat deletion and second-device checks pending |
| VSAFE-005 Avoid duplicate paid work and unauthorized grants | Unintended spend or premium access | ai_usage/openai_gateway, entitlement, storeDeadline | AI accounting root tests, entitlement/storeDeadline tests, subscription recovery component tests | Real store sandbox pending; never auto-retry purchases |
| VSAFE-006 Restore consistent user data | Interrupted restore loses data | libraryBackup staging/journal replay, deletion precedence | libraryBackup/libraryMaintenance integration tests | Physical process-kill and low-storage drill pending |
| VSAFE-007 Make extraction/output limits explicit | Incomplete import is mistaken for complete text; AI can be inaccurate | Explicit image/PDF OCR errors, no webpage truncation; report-answer flow | PDF/OCR root tests, oversized-page test, reporting component tests | Compare representative source documents manually before release |
| VSAFE-008 Verify and review changes | Passing tests hide untested paths or increasing complexity | Coverage thresholds, zero-warning JS/TS lint, complexity regression gate; native CodeQL/lint/model tests | CI checks and generated reports | Native CI for each release commit must pass; independent review pending |
| VSAFE-009 Detect operational failure and recover | Undetected crashes, exhausted budget/disk, unrecoverable ledger | ops-check, diagnostics, ledger-snapshot, release evidence validator | Existing diagnostics/backup tests; release_evidence.test.js | Host scheduling/alert routing, native crash provider and off-site recovery pending |
| VSAFE-010 Review residual security/privacy risk | Vulnerable tooling or exported private text | Expiring advisory exceptions, dependency gates, user-visible unencrypted export warning | npm/OSV policy gates, backup tests | Exposure review, backup encryption decision, legal disclosures and repository settings require release evidence |

For every change, reference the relevant VSAFE ID in the PR, retain exact-commit checks, and resolve findings with evidence or an explicit reviewed risk decision. A later change that invalidates a control reopens its row. Do not mark external checks completed based only on mocked tests.
